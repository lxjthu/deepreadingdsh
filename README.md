# dsh-deep-reading

DeepSeek Harness 文献研究插件。阅读助手不设登录页面、不要求输入 API Key；默认通过 `ctx.llm` 使用 dsh 当前默认模型与既有认证。选择账号模型时使用 dsh 登录；选择 API 提供方时复用 dsh 已保存的凭据。模型可用性、费用和限额随所选通道。

## 使用

插件适配桌面运行时 `0.2.2-rc.3`。业务 Python 需要安装 `upstream/requirements.txt` 中的依赖；本机已存在的环境可以直接复用。插件安装到 `desktop` profile 后，重新启动桌面应用。

在 dsh 原生左侧栏点击 **文献研究**，工作台直接显示在 dsh 主面板，创建主题、导入文件、精读及创意实验室都在面板内操作。内嵌页面通过 dsh 同源路由与自身访问认证连接后台，浏览器端不需要阅读助手的额外访问标识。也保留 `deep-reading-workbench` 技能和独立本地网页入口。

1. 创建研究主题。
2. 选择整个文件夹（包含子目录）、多选文件，或填写本机文件/目录路径，导入 PDF、Markdown 或 CNKI/WoS TXT；同一文献可加入多个主题。
3. 在文献库勾选论文，进入精读或创意实验室。
4. 在“任务与成果”中查看结果、打开原件、下载产物，或继续失败、中断的任务。

## 文件夹导入与文献库

文献库沿用本机 Deep Reading Agent 的 `BibEntry` 业务结构：题名、作者、年份、DOI、期刊、摘要、中译摘要、关键词、卷期页码、语言、来源、标签、笔记和置顶；每个条目关联原文附件、阅读状态、题录完整度及研究成果时间线。本地工作台继续使用既有 workspace 和主题关系，未接入在线项目数据库、用户认证或过期清理；既有资料不需要搬迁。

导入默认根据文件名和正文调用 dsh 当前模型提取题录，关键词作为可编辑标签；可能产生模型用量。不做网络题录查询，不猜测缺失字段。关闭自动整理时仅按本地显式标题和字段提取。模型整理失败时保留原文及本地题录，显示原因和待核对标记，重新导入可重试。详情页可校正元数据、编辑标签与笔记，并打开原文件、提取文本和研究成果。

文件夹按首次扫描清单逐文件处理，记录进度、重复、失败、待核对及跳过原因；失败后继续只重试失败文件，新增文件需另建导入任务。按原文 SHA256 跳过重复文件；相同 DOI 或无冲突且唯一的完整题名匹配可归并条目，保留所有原文附件及主题和任务引用。题名相似、DOI 冲突、年份或第一作者冲突时不自动合并。文件名本身不足以自动归并。支持 PDF 与 Markdown 的跨格式附件关联，不移动或重命名输入文件。

浏览器文件夹选择保留附件的相对目录信息；不支持的文件和 `.source.md` 说明文件会跳过。本机目录导入不跟随符号链接，不扫描隐藏目录或当前工作台资料目录。浏览器上传每个文件上限 65 MiB，较大文件请填本机路径。扫描 PDF 仍使用原有 Unlimited OCR 二代配置。

接口：`POST /api/import` 接受 `topic_id`、`path`（文件或目录）或 `paths`（文件条目数组）、`engine` 和 `auto_organize`；任务结果包含逐文件进度。`GET /api/library` 返回与条目、附件和任务记录对应的结构，`POST /api/library` 编辑 `entry_id` 的 `metadata`、`tags`、`note` 和 `is_pinned`。

## 已接入的任务

- 长文本维度精读、七步精读、四步精读与逐篇批量处理。
- 三类题录筛选、全文两步/分片翻译、摘要翻译、题录提取。
- 证据问答、参考文献提取、正文引用追踪、参考文献格式分析和排版。
- 跨文献比较、主题综述、知识卡片、单篇/多篇写作风格。
- 文献库检索意图分析、研究报告、论文评论、标签建议。
- 提示词工作区覆盖、阅读维度模板生成与 JSON 导入。
- 经济管理创意实验室：构念、机制、变量、六类证据缺口、候选选题、结合历史结果的模型深化。

单篇任务按所选文献串行执行。跨文献比较、综述和多篇风格至少需要两篇论文。摘要翻译需要已有摘要；参考文献排版需在高级模板变量中给出 `rules`，例如 `{"rules":"GB/T 7714"}`。核心校验会拒绝缺少必要输入的任务，不以猜测补齐研究事实。

长文本维度支持内置 ID 或中文名称；自定义维度在“提示词 → 导入自定义阅读维度”保存，随后在分析页选择模板。示例：

```json
{"dimensions":[{"name":"识别策略","instruction":"说明识别假设、外生变异来源和局限，引用原文。"}]}
```

创意实验室规则分析不调用模型；“用 dsh 深化构思”读取同一主题内上次已完成的实验室结果与当前文献证据。六类缺口是本次材料中的证据缺失，不代表整个领域没有相关研究，候选选题和假说需要核验。

## 本地 OCR

PDF 默认用 Unlimited OCR 二代逐页识别。复用本机 `C:/ocr/Unlimited-OCR-env`、`Unlimited-OCR-model` 与已部署的官方二代转换函数，保存原 PDF、原始识别、图片、页号和抽取结果；不下载模型、不安装 PyTorch。可靠文字层的 PDF 可显式选择快速提取。

安装包不含 Python、OCR 权重或共享 PyTorch。换电脑需要准备兼容环境，并在资料目录的 `runtime.json` 中指定：

```json
{
  "python": "C:/research-python/Scripts/python.exe",
  "ocrRoot": "C:/ocr",
  "ocrPython": "C:/ocr/Unlimited-OCR-env/Scripts/python.exe"
}
```

普通业务环境需要 Python 3.10+ 和 `upstream/requirements.txt`；OCR 单独使用既有 GPU 环境，不与普通业务环境合并。

## 数据与备份

初始资料目录由 `config.dataDir` 指定，未指定时为 `$DSH_HOME/deep-reading`（未设置 DSH_HOME 时使用 `~/.dsh`）。通过顶部“资料目录”保存的选择优先，持久化于 `$DSH_HOME/deep-reading-settings.json`。分发包不包含本机资料目录。升级旧版本先按 [升级说明](UPGRADE.md) 保留原路径。`topics.sqlite3` 保存主题、文献关联、任务和模型交接；`workspace/` 保存统一文献、原件、提示词覆盖、检查点和产物。没有用户角色或 24 小时资料清理。

关闭 dsh 会停止本插件的服务；中断任务重开后显示为可续办。已完成模型步骤保留。单个资料目录只允许一个工作台实例；另一 dsh 实例可使用插件配置的独立 `dataDir`。

“备份全部主题与文献”生成 ZIP，不含 dsh 凭据或插件运行连接标识。恢复时关闭当前工作台，指定**不存在的新目录**：

```powershell
python scripts/server.py --home D:/research/restored --restore D:/backups/research.zip
```

然后通过顶部“资料目录”启用恢复的新目录。恢复命令拒绝覆盖旧目录和压缩包越界路径。

## 安装与兼容

适配并使用安装版 `0.2.2-rc.3` 的消息构造与 Cordis 接口验证。通过支持的插件管理器安装本地包：

```powershell
dsh plugin --profile desktop add file:C:/packages/dsh-deep-reading-0.3.4.tgz
```

平台预发布接口可能变化；升级 dsh 后需重新核对兼容。源码测试与当前桌面验证见 `verification/desktop-0.3.4.md`。

验证记录见源码目录 `verification/`，实施范围见 `PLAN.md`。自动测试、模拟多步恢复、真实 OCR、真实 dsh 模型与浏览器验证分别记录；未逐项进行所有任务的真实模型准确性评测。


## 跨论文研究 Wiki（0.3.1）

在文献库勾选论文，打开“研究 Wiki”，点击“提取所选文献／更新 Wiki”。通过现有 dsh 模型处理所选全文，按 12,000 字符分段、1,000 字符重叠；方法、数据与附录均参与，题录和正文复用当前来源版本。任务显示分段进度，取消、失败或重启后可在“任务与成果”继续。

七类实体（理论、方法、变量／构念、作者、数据库／数据集、量表、案例）全库共享。研究主题只过滤实体列表；实体详情展示全库记录。实体页由结构化记录生成，提供论文使用／测量对照、定义与发现、原文证据、同篇实体导航、更新候选与历史。角色、样本、操作化和信效度属于论文使用记录。仅提及与实际采用分开，量表版本和案例边界保留独立实体。同名作者只有可靠标识匹配时才自动关联；其余通过候选选择或归并人工处理。

金色边框表示待核对，绿色表示已确认且来源有效。选择候选可批量确认或拒绝；陈旧候选必须重新核对，来源变化则重新抽取。人工可修改名称、别名、笔记和论文用法，改选实体、新建独立实体、归并及撤销归并。历史恢复先送审，确认后产生新版本；归并后的后续修改会阻止直接撤销，避免覆盖新修订。原文不会删除。来源变化的记录保留但停用，不进入研究上下文。

每条使用关系和知识陈述保存逐字引文、字符位置、来源版本及 SHA256；可靠页码存在时才显示页码。匹配引文只验证出处，不能证明解释正确。只有题录／摘要的文献仅整理有限信息。人工笔记独立展示，无须伪造论文证据。实体间有证据关系保存类型；共同论文导航明确标注，名称匹配仍可能需要消歧。

从实体页可选择当前主题内关联论文进入比较、综述或创意实验室。比较、综述与实验室深化纳入所选论文已确认、来源未变化的结构化记录；候选不会混成已确认上下文。规则实验室的结果单独包含 `wiki_confirmed`。

Wiki 表、候选、版本、归并和分段检查点存于原有 `topics.sqlite3`，独立 `wiki_meta` 记录数据版本。原文主库无需迁移，新表纳入已有 ZIP 一致性备份。恢复仍使用上面的新目录恢复方式。模型桥接没有工具或批准能力；审核操作由工作台界面提交。

验证：`python -m unittest discover -s test -p 'test_*.py'`、`npm test`、`node --check web/wiki.js`；隔离浏览器验证为 `python verification/wiki_browser.py`，复用本机 Playwright 浏览器。受控模型响应和虚构测试论文只验证流程，不表示真实论文抽取准确率。

## 资料目录设置（0.3.4）

“文献研究”面板顶部的“资料目录”显示实际生效路径，支持宿主原生“选择文件夹”和手工粘贴完整路径。点击“保存并启用”后验证目录，等待旧后台退出、新后台就绪，再持久化设置并重新加载工作台。取消不保存。空目录会初始化为新库；不兼容、损坏、来源不明的非空目录和被占用目录会被拒绝。运行、排队任务或尚未退出的执行实例存在时禁止切换。

切换不搬迁、合并、删除原资料，原目录仍可再次启用。保存或启动失败时尝试恢复旧后台；恢复失败显示真实失败状态，可通过“重试连接”重试，或选择另一个有效目录。无无限自动重启。桌面原生选择器由宿主 `directoryPicker` 提供；没有 native 能力的宿主请手工填写路径。

业务 Python、OCR 根目录和 OCR Python 属于本机设置。首次从原资料库 `runtime.json` 读取这些字段后存入机器设置文件，空库也能复用；OCR 执行时新库显式配置的 `runtime.json` 字段优先。不安装或修改 OCR、PyTorch 和模型。机器设置文件不包含凭据，也不随资料备份导出。

每次新模型请求读取宿主当前默认模型和推理强度；显式插件模型配置仍可覆盖它们。没有显式 `maxTokens` 时继承宿主提供商默认值。已完成且可复用的步骤保持原结果，不因切换模型重做。取消针对当前执行实例持续有效，立即续办不会取消旧实例的中断信号。

真实模型用量保存在 `calls.response`、任务的 `model_calls` 字段，以及精读步骤记录中的 `usage`。没有返回用量时保留未知值，不填零、不估算。直接使用 `ctx.llm` 复用路由与认证，不创建聊天 Session，也不自动计入桌面聊天统计。

Wiki 抽取对 PDF 换行导致的纯空白差异，只在当前分段中唯一匹配时定位回原文，保存实际原文、原始模型引文与 whitespace_only 标记。正文字符、标点的差异、位置歧义和错误显式位置仍拒绝；候选继续等待人工核对。

Wiki 候选校验失败时有一轮带校验反馈的模型修正，修正结果仍执行相同严格校验；再次失败会停止该分段，不写入未经验证的检查点。跨页脚注打断的句子必须使用多个连续原文片段，不能拼接成逐字引文。修正调用的真实用量也计入任务记录。
